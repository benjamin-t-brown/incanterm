## Project asset editor

[ed-ascii](../../ed-ascii/README.md) remains in `ed-ascii/` as the previous painter and an import source. Asset authoring now runs in the Vite editor described in [Assets and scene editor](assets-and-scene-editor.md).

## Other art tools considered

These are candidates, not installed tools or a finalized asset pipeline:

- [Moebius](https://github.com/blocktronics/moebius): direct ASCII/ANSI drawing, including half-block brushes; Windows, Linux, and macOS.
- [Durdraw](https://github.com/durdraw/durdraw): terminal art and frame animation editor for Unix-like systems; compressed JSON native assets could be imported.
- [ascii-image-converter](https://github.com/TheZoraiz/ascii-image-converter): image-to-ASCII/Braille conversion.
- [Chafa](https://hpjansson.org/chafa/): image and animated GIF conversion; select symbol output rather than graphical image protocols for the SSH path.
- [ascii-motion](https://c4rl0s04.github.io/ascii-motion/): video-to-text/ANSI conversion and frame export.

Import character/color data into the game's own asset format. A video that merely depicts ASCII characters is not directly a terminal asset.
